1起点、终点、障碍
A* 解决的是这个基本问题：在一个网格地图里，从起点 S 走到终点 E，绕过障碍，找到最短路径。 每一步只能上下左右（或加上对角）移动一格。
2三个集合：open / closed / path
A* 维护三个集合，所有节点非此即彼：
open（开放列表）：已经发现、还没考察的"候选节点"，相当于待办清单。
closed（关闭列表）：已经考察过、邻居都处理完了的节点，已办。
path（路径）：最终回溯出来的从 S 到 E 的路径。
open 待办
closed 已办
path 路径
墙 障碍
3代价函数 f = g + h
每个候选节点都有一个"优先级" f，由两部分组成： f(n) = g(n) + h(n)
g(n)：从起点 S 走到 n 的真实代价（已花费）。
h(n)：从 n 到终点 E 的估算代价（启发式）。
直觉上：g 看你已经走了多远，h 看你还得走多远。f 越小说明这条路"看起来越短"，越值得先看。
4启发式 h：估算的学问
h 是 A* 的灵魂。不能高估真实最短距离（否则 A* 不保证最优），常用的有：
曼哈顿距离（4 方向）：|dx| + |dy|
对角距离 / octile（8 方向）：max(dx,dy) + (√2-1)·min(dx,dy)
欧氏距离：√(dx² + dy²)，连续空间常用
本演示使用 octile（八方向 + 对角代价 √2）。
5A* 的核心循环
循环三件事，直到终点被加入 closed：
① 取：从 open 中拿出 f 最小的节点 → current
② 移：把 current 从 open 移到 closed
③ 扩：遍历 current 的邻居；对每个邻居计算新 g'，如果 g' < 旧 g，就更新它的 g/h/f 和 parent，并塞进 open
parent 指针记录"我从哪儿来"，最后用来反向回溯出完整路径。
6松弛操作：为什么可能多次更新？
邻居的 g 不一定第一次就拿到最优值——可能从另一条更近的路绕过来时更小。所以每次扩展都要"松弛"（relaxation）： if g(候选) + w < g(邻居) then 更新 这就是为什么 A* 能保证找到最短路径（Dijkstra 也有这步）。
7回溯出最终路径
终点进入 closed 后，沿 parent 指针一路从 E反向跳回 S，得到的节点序列反转一下就是 S→E 的最短路径。
parent 数组是 A* 的"记忆"。
路径不一定唯一（f 相等时），但每条都最短。
